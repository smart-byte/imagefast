Quick start

Create a pool once. Every call returns a promise and does its work in a worker.

thumbnails.ts 
import { createImageFast } from 'imagefast';

const fast = createImageFast();

// Header only. No pixels are decoded.
const { width, height } = await fast.dimensions(file);

// Decoded, resized and encoded in a worker.
const { blob } = await fast.thumbnail(file, {
  width: 640,
  type: 'image/webp',
});

// Or the same pixels for a canvas, without encoding.
const { bitmap } = await fast.bitmap(file, { width: 640 });

  1. Dimensions without decoding

    dimensions() reads the first 64 KB and parses the header, EXIF orientation included. A 50 MB photo takes well under a millisecond.

  2. Pixels off the main thread

    Decoding, orientation, resizing and encoding run in workers that start on demand and exit when idle.

  3. No wasted work

    Thumbnails never upscale. Small files that already fit pass through untouched. RAW files use the camera’s embedded preview before a full decode.

Method and full results

API

Six methods on one object. Every call takes an AbortSignal.

dimensions(file)
Oriented width and height, the format, and how they were read.
thumbnail(file, options)
A JPEG, WebP or PNG blob that fits or fills a box. Never upscales.
bitmap(file, options)
The same pixels as an ImageBitmap for a canvas. No encode.
decodeRaw(file, options)
A RAW file’s JPEG preview with camera details. Needs the RAW plugin.
stats()
Pool size, live and busy workers, queued jobs.
terminate()
Stops the workers and rejects pending calls.

workers and idleMs size the pool. Full reference

Questions

Do images leave the browser?

No. Everything runs locally in Web Workers. There is no upload service; your app decides what happens with the result.

Which browsers are supported?

Chrome and Edge 94+, Firefox 114+ and Safari 17+. It needs module workers, createImageBitmap and OffscreenCanvas.

Does it work with React, Vue or Svelte?

Yes. It has no framework code and returns promises. Create it in browser code, after mount if you render on the server.

Does it replace server-side processing?

No. It prepares images before upload: previews, thumbnails, local workflows. On the server, use a library such as sharp.
